X and plus quadcopter geometry: why the front direction matters

By YANAPublished 27 October 20263 min read

X and plus describe how four motor positions are oriented relative to the vehicle’s forward direction. The same square of motor locations can be described differently after the front changes. Flight software must use a geometry consistent with the actual vehicle; the visual outline alone does not establish the correct configuration.

Begin with motor positions and a front arrow

Draw four motor centres at the corners of a square. Put the forward arrow between two front motors for an X-style drawing. For a plus-style drawing, orient the front towards a motor. The difference concerns the relationship between axes and actuators. Keep motor identifiers separate from arm colours, because cosmetic colouring is not a universal numbering convention.

Geometry explains moments

A vertical force acting at a distance from the centre can produce a rotational moment. The relevant perpendicular distances differ for a given axis when the motor pattern is rotated. Use equal paper arrows to compare which motor forces contribute to a roll moment. No powered motor test is needed to understand why geometric information belongs in the control-system model.

Frame class and frame type are separate choices

ArduPilot distinguishes frame class from frame type in its configuration documentation. Four motors establish a broad arrangement, but the selected geometry must still match. Students should record the actual software stack and version before looking at any configuration screenshot. Do not transfer a parameter value from a different vehicle solely because both have four arms.

Numbering belongs to an implementation

A clockwise drawing labelled one to four is a useful classroom identifier, but it is not automatically the software’s output mapping. Treat your paper labels as local labels and state that explicitly. For a real setup, use the specific stack’s motor diagram and manufacturer documentation. Mixing a paper convention with a firmware convention can create a convincing but incorrect wiring plan.

Build a geometry explanation that survives rotation

Ask another team to rotate your drawing and identify the front, axes and motor locations without using the page edges as clues. If they cannot, the diagram needs better labels. The result should explain why orientation matters and list the documentation required for an actual setup, rather than provide unverified operational configuration instructions.

  • Mark forward and vehicle axes.
  • Separate arm colour from motor identity.
  • Use the actual stack’s geometry reference.
  • Keep classroom labels distinct from output mapping.

Rotate one paper airframe

  1. Cut a square paper model with four marked motor positions and a removable front arrow.
  2. Place the arrow towards a side midpoint, then towards a corner, and sketch the resulting axis relationships.
  3. Mark a hypothetical upward force at each corner and identify which have leverage about a chosen axis.
  4. Exchange diagrams and test whether a second team can recover the intended geometry without additional explanation.

Questions

Does changing arm colour change the frame type?

No. Colours may be useful visual markers, but geometry is defined by physical motor positions and the chosen vehicle forward direction.

Can I use any four-motor numbering diagram?

No. Use the reference for the actual flight stack, frame geometry and version, then verify it against the hardware. Numbering conventions are not universal.
