Gyroscope bias: why a stationary sensor can suggest rotation

By YANAPublished 27 October 20263 min read

In this guide

  1. Rate is not angle
  2. Use an explicitly fictional offset
  3. Noise and bias leave different clues
  4. Calibration belongs to the actual system
  5. Explain what the simple model omits
  6. Practical activity
  7. Questions
  8. References

A gyroscope measures angular rate, and a small offset can remain even when it is stationary. Integrating that offset over time produces a growing angle error in a simple model. A classroom spreadsheet can illustrate the difference between random noise and persistent bias without modifying a real controller’s calibration.

Rate is not angle

A rate of two degrees per second describes how quickly orientation changes, not an orientation of two degrees. Multiplying a constant rate by an elapsed time gives an angle change in a simplified one-axis example. Label units in every column. This small distinction prevents confusion when students compare an attitude trace with the gyroscope data used to support it.

Use an explicitly fictional offset

Imagine a stationary classroom sensor reporting a constant positive 0.2 degrees per second. Over ten seconds, a naive integration yields two degrees of apparent rotation. The sensor did not actually turn in this model. The number is chosen for arithmetic clarity and does not describe any Pixhawk or YANA sensor. Record the assumed sample interval before computing each increment.

Noise and bias leave different clues

Create a second dataset whose values alternate between positive and negative deviations around zero. Its short-term readings look less smooth, but its accumulated behaviour differs from the persistent offset. A mean value and a time plot answer different questions. One short recording may not reveal temperature-related change or other longer-term effects, so avoid turning a classroom pattern into a universal diagnosis.

Calibration belongs to the actual system

PX4’s gyroscope documentation places the sensor within attitude estimation and links to the stack’s calibration process. Real procedures and requirements depend on the controller and software. This lesson explains why calibration matters; it does not provide a substitute procedure. Do not write a manually estimated spreadsheet offset into an operational controller based only on this exercise.

Explain what the simple model omits

Real attitude estimation involves three-dimensional motion, timing, filtering and other information. The one-axis sum deliberately excludes those complications. Ask students to state which conclusion is supported: a persistent rate offset can accumulate. It does not establish how a particular flight stack handles that offset or predict a real aircraft’s attitude error.

  • Keep angular rate and angle units distinct.
  • Use the documented sample interval.
  • Compare persistent offset with varying noise.
  • Label all classroom sensor values as fictional.

Integrate two invented gyro recordings

  1. Create ten one-second samples of positive 0.2 degrees per second in a spreadsheet.
  2. Calculate cumulative angle, then repeat with alternating positive and negative 0.2 readings.
  3. Plot both rates and accumulated angles with units and the same time axis.
  4. Write the supported conclusion and three reasons the result cannot predict a real controller’s attitude estimate.

Questions

Does a nonzero stationary reading prove the sensor is faulty?

Not by itself. Measurement noise, bias, temperature and processing need context. Follow the actual hardware and stack’s documented checks.

Should I use this exercise to change calibration values?

No. It is a conceptual spreadsheet model. Actual calibration must follow the verified procedure for the real controller and firmware.
