Keep an engineering notebook for a drone learning project

By YANAPublished 27 October 20263 min read

Record what you intended to investigate, what you actually observed and what you changed. Keep interpretation separate from raw evidence, and include dates, component identifiers and software versions where relevant. A useful notebook lets another learner reconstruct your reasoning without relying on the memory of the most experienced team member.

Use a repeatable entry structure

Start an entry with the date, purpose and equipment state. Add the planned task, observation and next decision. Record who participated and where supporting files are stored. A short, consistent entry is more useful than an elaborate template nobody completes. Do not overwrite a mistaken observation silently; add a correction and explain what evidence changed your understanding.

Distinguish observation from interpretation

The display showed a particular warning is an observation. The controller is broken is an interpretation that needs further evidence. Write them in separate fields. This makes review more productive because a supervisor can question the explanation without losing the original record. Photograph labels or save screenshots when appropriate, while avoiding passwords, private locations and unnecessary personal information.

Preserve versions and provenance

Name files so they can be associated with the session and equipment state. Keep original data separate from edited charts. If a sample comes from simulation, identify it clearly. For software work, record the source revision and environment. For shared equipment, link the notebook entry to the maintenance or configuration record so later students know which physical state produced the evidence.

Example: document an inconclusive check

A team cannot establish whether a connector matches its diagram because the supplied drawing lacks a pin view. The notebook should record the visible identifier, photograph reference, document revision and precise unanswered question. The next action is to obtain a verified diagram, not try alternative connections. An honest unresolved result protects the quality of the project’s reasoning.

Review the notebook during the project

Use brief supervisor reviews to identify missing context before it is forgotten. Select one entry and ask another student to explain the sequence from the record alone. NASA’s design-process resource provides useful context for recording iteration; the notebook structure here is a suggested working method. Finish with a handover index linking final documents, abandoned approaches and open questions.

  • Date entries and identify the equipment state.
  • Separate observations from interpretations.
  • Link original files and document versions.
  • Preserve corrections and unresolved questions.

Try a reconstruction review

  1. Choose an entry from the previous week.
  2. Ask a teammate who was absent to explain the task and result.
  3. Add the context they needed but could not find.

Questions

Can the notebook be digital?

Yes. Choose a system your institution can retain and export, with sensible access and a clear revision history.

Should failed attempts be included?

Yes, when relevant. They explain decisions and prevent others repeating an unsuitable approach, provided observations and interpretations are clearly distinguished.
