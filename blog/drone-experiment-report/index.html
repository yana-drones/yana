Write a drone experiment report that another student can assess

By YANAPublished 27 October 20263 min read

In this guide

  1. Start with one question and a prediction
  2. Describe the configuration that matters
  3. Keep evidence and processing traceable
  4. Write the result before the explanation
  5. Close with scope and the next useful test
  6. Practical activity
  7. Questions
  8. References

A useful experiment report connects a defined question to a reproducible method, original evidence and a bounded conclusion. Include configuration, units, processing and uncertainty. Explain mismatches rather than hiding them. Whether the exercise uses cardboard, supplied logs or simulation, a reader should be able to distinguish observation from calculation and hypothesis.

Start with one question and a prediction

“We explored drones” does not tell a reader what was investigated. “We compared the mean of one fictional sensor trace before and after adding a known offset” does. Write the prediction before examining the outcome. This reduces the temptation to invent a successful story after seeing a graph, and it makes an unexpected result educationally useful.

Describe the configuration that matters

Record whether the activity used a paper model, disconnected hardware, supplied recording or simulator. For software, include stack, tool, model and version information. For a recording, keep the log format and field dictionary. PX4’s ULog specification illustrates that logs contain defined data types and message information; a screenshot alone loses much of that structure.

Keep evidence and processing traceable

Retain the original dataset, list any conversions and give meaningful labels to tables or plots. Include the exact time window and treatment of missing samples. A second student should be able to follow one reported number back to its source. If the data is invented for teaching, state that clearly rather than describing it as an actual aircraft observation.

Write the result before the explanation

Describe the calculated difference or visible pattern, then discuss possible reasons. A disagreement with the prediction may expose a unit error, an incomplete model or a genuine limitation. Do not erase it by changing the prediction retrospectively. A clear report can explain why the evidence is insufficient for a unique cause and propose a discriminating next observation.

Close with scope and the next useful test

The conclusion should answer the initial question within the method’s boundaries. A simulated response cannot certify real hardware, and a cardboard balance exercise cannot establish payload. Name the most useful unresolved question and the evidence needed to address it. This creates a practical handover to the next class rather than ending with a generic claim that the drone worked well.

  • State the question and prior prediction.
  • Record configuration and original data.
  • Document conversions and excluded samples.
  • Separate result, explanation and next test.

Review a one-page technical report

  1. Use a fictional gyro-offset spreadsheet or paper centre-of-mass calculation from an earlier lesson.
  2. Write a one-page report containing question, prediction, method, evidence and limitations.
  3. Exchange reports and ask reviewers to trace one number to its input and identify one unsupported claim.
  4. Revise the conclusion to match the available evidence and specify a next observation that would resolve an actual uncertainty.

Questions

Should a report hide an unexpected result?

No. Preserve it, check the method and definitions, and explain what evidence would distinguish possible causes. Unexpected results can reveal valuable learning questions.

Can a classroom report be used as a product performance claim?

Only if the evidence genuinely supports that exact claim under suitable conditions. Fictional examples, simplified models and simulation alone do not establish aircraft performance.
