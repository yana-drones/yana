Telemetry packet gaps: distinguish missing data from a stopped system

By YANAPublished 27 October 20263 min read

In this guide

  2. Sequence numbers add structure
  3. A repeating value can still be stale
  4. Do not fill gaps without an explained rule
  5. Write a communications conclusion, then a hypothesis
  6. Practical activity
  7. Questions
  8. References

A gap in received telemetry means the observer lacks some expected information; it does not uniquely identify why. Packet sequence, source identity, timestamps and recording boundaries help investigate. Sequence counters can wrap, and traffic from different sources must not be mixed carelessly. Treat a missing sample as uncertainty rather than inventing a physical event.

Name the observer and transport boundary

A ground-station recording contains what reached that observer through its configured link and logger. The aircraft may have produced information that was not recorded there. Draw sender, transport and recorder as distinct boxes. Ask where evidence would be needed to distinguish a sender problem from a transport or logging problem before attributing a gap to hardware failure.

Sequence numbers add structure

MAVLink’s serialization documentation includes a packet sequence field alongside system and component identifiers. These support packet interpretation, but a naive subtraction is insufficient when identities or counter wrap are ignored. Use fictional small counters in a paper exercise so students can see the principle without claiming that the classroom format reproduces every real protocol detail.

A repeating value can still be stale

A display may hold the last received value when new information stops arriving. The number can remain physically plausible. Include age or freshness in a conceptual display design rather than treating a static line as proof of a stable aircraft state. A zero, a held value and an unavailable value should have distinguishable meanings.

Do not fill gaps without an explained rule

Interpolation can be useful for some analyses, but it creates inferred points rather than restoring missing measurements. Keep original data and show gaps when they matter. For a classroom trajectory, draw two possible paths between the same available endpoints. Their difference demonstrates why a straight connecting line should not be mistaken for a recorded route.

Write a communications conclusion, then a hypothesis

A report can establish that particular messages were not present in the supplied recording during a stated interval. It should separately list possible causes and the evidence needed to distinguish them. Avoid inferring actual loss rate from an undocumented mixture of sources. Operational link and failsafe decisions need the actual system documentation and appropriate review.

  • Identify sender, recorder and transport.
  • Keep source identity with sequence values.
  • Handle wrap and unavailable data explicitly.
  • Mark interpolation as inference rather than measurement.

Find a gap in a paper packet stream

  1. Create fictional packets with source labels and a counter from zero to seven, explicitly using a classroom-sized counter.
  2. Remove one packet, wrap the counter and interleave a second source.
  3. Ask students to identify what they can and cannot infer without mixing source sequences.
  4. Draw two possible physical trajectories through the same missing interval and explain why received endpoints do not establish the route.

Questions

Does missing telemetry mean the aircraft stopped processing?

No. Sender, transport and recorder behaviour need separate evidence. A missing ground record does not uniquely establish onboard state.

Can I replace every missing value with the previous value?

Only through a clearly stated analysis or display rule, and it must remain identifiable as held or inferred data rather than a new measurement.
