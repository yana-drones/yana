Document quadcopter connections without relying on cable colours

By YANAPublished 27 October 20263 min read

Document both ends of each connection, its purpose and the source used to verify it. Include connector orientation and identifiers where confirmed. Cable colour alone is insufficient evidence of function. Keep the assembly unpowered while preparing a read-only map, and leave unresolved connections marked for competent review.

Start with subsystem boundaries

Draw broad blocks for power distribution, flight controller, receiver, ESCs and motors before documenting individual connections. Separate electrical power paths from command or data paths. This first diagram should explain relationships without implying that every pin assignment has been checked. A high-level map and a detailed connection table answer different questions and should refer to each other.

Record both ends and the evidence

For each cable, note the exact component identifiers, connector labels and document revision used. Include whether a diagram is viewed from the cable side or board side when the source establishes that detail. If the view is unknown, state that plainly. Do not copy an illustration for a similar-looking board and treat it as verification of the actual hardware.

Make uncertainty easy to see

Use a text status column such as verified from documentation, visually observed or unresolved. Do not rely only on colour to distinguish those states. A component may be visible in a photograph while its electrical function remains unknown. Link questions to the project notebook and assign someone to obtain the relevant manufacturer information before any connection is approved.

Example: a swapped reference image

A student notices that a controller in an online tutorial has a different connector arrangement from the classroom unit. The correct response is to retain the tutorial as general context and create a separate unresolved entry for the actual board. Photograph its identifier and request the correct documentation. The mismatch becomes a lesson in evidence quality rather than a reason to improvise wiring.

Review before using the document

Have a competent reviewer compare the table with the unpowered assembly and source documents. Record changes and sign-off scope. A reviewed drawing is still not a complete aircraft-readiness assessment. ArduPilot’s hardware setup pages provide general configuration context, but exact component documentation and the agreed system configuration determine the applicable connection details. Keep the final reference with the equipment.

  • Name both components and connector ends.
  • Record orientation and document revision.
  • Separate power and signal diagrams.
  • Leave uncertain mappings unresolved pending review.

Create a read-only connection table

  1. Select one documented interface on disconnected equipment.
  2. Record endpoints, purpose, source and review status.
  3. Ask another reader whether the connector view is unambiguous.

Questions

Can I identify a wire by colour?

Colour can help locate a wire but does not independently verify its purpose or compatibility. Check the actual component documentation.

Is a photograph enough as a wiring diagram?

It helps show routing and physical state, but may hide labels, connector orientation and electrical details. Pair it with verified references.
