Motor output mapping: separate location, command and connector

By YANAPublished 27 October 20263 min read

  4. Rotation direction is another independent property

  7. Questions
  8. References

Motor mapping links a motor’s physical location to a logical actuator function and a controller output. Those are three separate identifiers. A neat row of wires does not prove the mapping is correct. Learn the relationship on paper, then leave actual output verification to the documented, supervised process with propellers removed.

Give the physical positions neutral labels

Start with front-left, front-right, rear-left and rear-right on a clearly oriented drawing. These descriptions concern geometry rather than firmware numbering. A second team should be able to find each position after rotating the sheet. If you use local labels such as A to D, write that they are classroom identifiers and not the flight stack’s motor numbers.

Add the logical actuator layer

The software associates actuator functions with the vehicle model. The exact conventions depend on stack and configuration. PX4’s actuator documentation separates geometry from assigning outputs, which is a useful conceptual distinction. A selected quadcopter geometry and a four-wire connection are incomplete unless the mapping between those layers is also correct and verified.

Connect the logical layer to physical outputs

A labelled controller pin or connector is a physical endpoint. Its configured function may need explicit review. Draw a three-column table: physical position, logical function and physical output. Leave cells blank until a verified reference supplies them. A copied diagram from another stack can appear orderly while connecting the wrong meanings, so record the source and version.

Rotation direction is another independent property

A motor’s location and output mapping do not establish its mechanical rotation or propeller suitability. Add these as separate conceptual fields rather than hiding them in one motor-number label. This article deliberately avoids a universal wiring or motor-test sequence. Real checks must follow exact hardware and stack documentation with suitable supervision and propellers removed.

Use inconsistency to teach diagnosis

On a fictional table, swap two output labels and ask which documents would reveal the inconsistency. A paper mapping audit can distinguish a wrong drawing from a wrong configuration without energising anything. The final record should identify the assumed front, actual stack and reference diagram. It is an explanation tool, not evidence that an untested physical installation is ready.

  • Separate position, logical function and physical output.
  • Record the stack and geometry reference.
  • Keep rotation direction as a separate check.
  • Do not use classroom numbering as a wiring instruction.

Audit a three-layer motor table

  1. Draw a paper quadcopter with neutral A-to-D position labels and a front arrow.
  2. Provide a fictional logical mapping and output table with one deliberate swapped entry.
  3. Ask teams to identify the inconsistency and explain which layer contains the error.
  4. Add a separate rotation-direction column and list the real documentation needed before any physical verification.

Questions

Does motor one always mean the front-left motor?

No. Conventions depend on the software and geometry. Use the actual reference for the specific system.

Does correct output mapping establish correct propeller installation?

No. Mapping, rotation direction and propeller suitability are separate properties and need their own documented verification.
