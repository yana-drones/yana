Plan a drone workshop for learners with mixed experience

By YANAPublished 27 October 20263 min read

  2. Choose a common question
  3. Prevent expertise from taking over
  4. Example: a connection map with extensions
  5. Review participation as well as completion

  7. Questions
  8. References

Use one shared learning question with tasks at different depths. Beginners can identify and explain components while experienced learners check assumptions against documentation. Keep access to tools based on the agreed supervision plan, and assess understanding individually so confident participants do not represent the entire group.

Discover experience before teaching

Ask learners what they have actually done: read a circuit diagram, assembled mechanical parts, used a ground station or analysed data. Avoid a single beginner-or-expert label. Someone comfortable with software may still be new to power connections. Use the responses to plan examples and support. Keep the questionnaire brief and explain that it helps allocate learning opportunities, not rank students publicly.

Choose a common question

A question such as how a command reaches a motor can involve everyone. Beginners trace named blocks while experienced participants identify interfaces and documentation gaps. The group can compare answers without splitting into separate unrelated lessons. Keep the final output common enough to review together, then offer a deeper extension for those who finish early.

Prevent expertise from taking over

Assign a checking role that requires an experienced learner to explain reasoning rather than complete all the work. Rotate who handles the reference diagram and who presents conclusions. Ask individuals to write a short explanation before the group discussion. This gives quieter learners a way to contribute and shows where apparently successful teamwork hides confusion.

Example: a connection map with extensions

Provide an unpowered assembly and ask everyone to map its major subsystems. An extension could ask which connector details must be verified before a replacement component is purchased. A second extension might compare two documented interface descriptions. Neither extension needs to involve powered experimentation. Review the basic map first so advanced questions do not overwhelm learners who are still learning names.

Review participation as well as completion

At the end, ask each learner to explain a component they did not initially understand and one question they would investigate next. Use the responses to choose follow-up material. Cornell recommends planning group work stages and evaluation deliberately; the role and extension structure here is an original application of that principle. Adjust the next session from observed needs rather than assumed ability.

  • Ask about specific prior tasks.
  • Use one common question and optional extensions.
  • Rotate handling, checking and explanation roles.
  • Collect an individual explanation from everyone.

Create a two-depth task sheet

  1. Write a basic task that produces a component diagram.
  2. Add an extension that checks a technical assumption using documentation.
  3. Make both tasks end with an explanation rather than a speed contest.

Questions

Should beginners and experienced students be separated?

Sometimes, but not automatically. A shared task with different depths can work when supervision and participation are planned.

Can experienced students supervise powered work?

Do not assume that. The provider and host must explicitly agree who is competent and authorised for each supervised activity.
