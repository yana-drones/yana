SITL and HITL: where the real flight controller enters the loop

By YANAPublished 27 October 20263 min read

In SITL, flight software runs on a computer with a simulated vehicle. In hardware-in-the-loop, a real controller participates in a documented simulation setup. The boundary changes which hardware is exercised. Neither label alone proves that the physical propulsion system, installation or complete aircraft has been tested.

Draw the boundary before comparing the methods

Make two architecture diagrams and colour only the components that are real physical devices. The ground-station computer can be real in both diagrams, while the controller’s role differs. PX4’s simulation overview distinguishes SITL and HITL in this way. This system-boundary approach is clearer than describing one as realistic and the other as fake.

Ask which question needs hardware participation

A lesson about message interpretation may need no physical board. A specialised integration investigation may require actual controller participation under supported conditions. State the question before choosing the method. Introducing hardware simply to make an exercise look more practical can add setup complexity without providing evidence relevant to the learning objective.

Compatibility remains specific to the setup

HITL support depends on the actual controller, firmware and simulator arrangement. A Pixhawk-family name is not a universal compatibility statement. YANA’s proposed Pixhawk 2.4.8 therefore cannot be assumed to support any current hardware-in-the-loop workflow without verification. Use current official instructions matched to the actual board and intended flight-stack version.

Keep propulsion outside introductory exercises

A conceptual comparison can use paper diagrams and supplied recordings. Actual hardware-in-the-loop work requires the documented installation and qualified supervision, with propulsion prevented from creating hazards according to the official process. This article gives no hardware activation sequence. The educational aim is to understand what is in the loop, not to improvise an energised aircraft test.

Interpret the evidence at the right boundary

A successful HITL interaction can provide evidence about the participating controller and interfaces under the configured simulation conditions. It does not test real propeller aerodynamics, battery endurance or frame assembly merely because a board was present. Write the conclusion around the actual boundary, and identify which real components or environmental effects were still represented by models.

  • Colour real and simulated components separately.
  • Choose the method for a defined question.
  • Verify actual hardware and firmware support.
  • Limit conclusions to the exercised boundary.

Colour the simulation boundary

  1. Draw a computer-only flight stack and a separate diagram with a real controller exchanging simulated sensor data.
  2. Give teams four questions concerning field units, board communication, propeller thrust and frame inspection.
  3. Ask which questions each diagram can address and which need different evidence entirely.
  4. Add a proposed older controller label and write the compatibility questions that must be resolved before planning a real HITL session.

Questions

Is HITL always the better choice for a beginner?

No. Choose the simplest documented method that answers the learning question. SITL or supplied recordings can be sufficient for many introductory topics.

Does HITL test actual flight time?

Not merely by involving a controller. Real energy use and aircraft endurance require appropriate evidence for the actual complete system and conditions.
